# 🧁 ระบบจัดการร้านขนม

เว็บแอปสำหรับคนทำขนมขายเป็นอาชีพเสริม — แทนการจดบัญชีกระจัดกระจาย
ด้วยตัวเลขต้นทุนจริงที่ **รวมค่าแรงและเวลา** ไม่ใช่แค่ค่าวัตถุดิบ

## หลักคิดของแอปนี้

```
ต้นทุนจริงต่อชิ้น = (วัตถุดิบ + ค่าแรง + ค่าแฝง) ÷ จำนวนที่ได้ต่อรอบ

กำไรขั้นต้น = ยอดขาย − ต้นทุนวัตถุดิบ
กำไรสุทธิ   = ยอดขาย − ต้นทุนจริงต่อชิ้น − ส่วนแบ่งช่องทาง − ค่าส่ง
```

ทุกหน้าจะแสดง **สองตัวเลขคู่กันเสมอ** เพราะช่องว่างระหว่างมันคือค่าแรงที่มัก
ถูกลืม เช่น บราวนี่ 24 ชิ้น (วัตถุดิบ 380 · แรง 3.5 ชม.×150 · แฝง 120)
ขาย 10 ชิ้นราคา 60 ฝากร้านหัก 30% ค่าส่ง 50:

| | |
|---|---|
| กำไรขั้นต้น | **+441.67** ← ดูเหมือนได้กำไร |
| กำไรสุทธิ | **−57.08** ← ความจริงคือขาดทุน |

## Stack

- **Next.js 15** (App Router, Server Actions) — deploy บน Vercel
- **Supabase** — Postgres + Auth (เข้าจากเครื่องไหนก็เห็นข้อมูลเดียวกัน)
- **Tailwind CSS v4**

## ติดตั้ง

### 1. สร้างโปรเจค Supabase

ไปที่ [supabase.com](https://supabase.com) → New project → จดรหัสฐานข้อมูลไว้

### 2. สร้างตาราง

Supabase Dashboard → **SQL Editor** → New query → คัดลอกทั้งหมดจาก
[`supabase/schema.sql`](supabase/schema.sql) ไปวาง → **Run**

ไฟล์นี้รันซ้ำได้ปลอดภัย ถ้าต้องแก้แล้วรันใหม่

### 3. ใส่ค่าเชื่อมต่อ

Dashboard → **Project Settings → API** แล้วก๊อป 2 ค่าใส่ `.env.local`:

```bash
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
```

> `anon key` เป็น public key ปลอดภัยที่จะอยู่ฝั่ง client เพราะทุกตารางเปิด
> Row Level Security ไว้ — แต่ละบัญชีเห็นเฉพาะข้อมูลตัวเอง

### 4. รัน

```bash
npm install && npm run dev
```

เปิด http://localhost:3000 → กด **สมัครใหม่** → ระบบจะสร้างค่าตั้งต้นและ
ช่องทาง "ขายเอง" ให้อัตโนมัติ

> ถ้าไม่อยากยืนยันอีเมลตอนสมัคร: Dashboard → Authentication → Providers →
> Email → ปิด **Confirm email**

### 5. ตั้งค่าแรงก่อนใช้งานจริง

ไปหน้า **ตั้งค่า** ใส่ค่าแรงต่อชั่วโมงของตัวเอง — ถ้าไม่ใส่ กำไรสุทธิจะ
เท่ากับกำไรขั้นต้น และแอปนี้ก็จะไม่ต่างจากสมุดจดเล่มเดิม

## ลำดับการใช้งาน

1. **สินค้า** — เพิ่มขนมแต่ละชนิด + ราคาขายมาตรฐาน
2. **ช่องทาง** — ขายเอง / ฝากร้าน (หัก %) / ส่งราคาคงที่
3. **รอบผลิต** — ทุกครั้งที่ทำขนม บันทึกวัตถุดิบ+เวลา+จำนวนที่ได้
   → เห็นต้นทุนจริงต่อชิ้นทันทีระหว่างกรอก และตัดเข้าสต๊อกอัตโนมัติ
4. **ขาย/ฝาก** — เลือกสินค้า+ช่องทาง+จำนวน → ตัดสต๊อก คิดกำไรให้
5. **รายงาน** — ดูว่าขนมชนิดไหน/ช่องทางไหนคุ้มแรงจริง

## รายละเอียดที่ตั้งใจออกแบบไว้

- **ค่าแรงถูก snapshot ติดไปกับแต่ละรอบผลิต** — ปรับค่าแรงวันนี้
  รอบผลิตเก่าไม่เปลี่ยนตาม ประวัติกำไรจึงยังตรงกับความจริง
- **ต้นทุนถูก snapshot ตอนขาย** ด้วยค่าเฉลี่ยถ่วงน้ำหนักจากทุกรอบผลิต —
  ผลิตรอบใหม่ราคาต่างออกไป กำไรของรายการเก่าไม่ขยับ
- **สต๊อกคำนวณสดจาก ผลิต − ขาย** ไม่ได้เก็บเป็นตัวเลขนิ่ง ๆ จึงไม่มีทาง
  เพี้ยนแม้จะลบหรือแก้รายการย้อนหลัง
- **วัตถุดิบกรอกได้ 2 แบบ** — ยอดรวมรอบนี้ (เร็ว) หรือแยกทีละอย่าง (ละเอียด)
